### Move the admin API image from Docker Hub to a private ECR repository

**Revision note (2026-11-23, against the actual AWS setup):** the ECR repository name is `beerpassport-admin-api` everywhere in this PR (an earlier draft used a hyphenated variant in the workflow, both IAM examples, the SSM document, and the runbook; corrected). The unsupported `Comment` keys were removed from both IAM policy examples and the policies were re-validated as JSON with only IAM-supported statement keys. The setup checklist now records what already exists (ECR repository, the deployment role's push permission, the managed node, SSM document version 1) instead of recreating it, and the pull path is gated on a real ECR login and pull verified on the host.

**The workflow change, identified exactly:** `.github/workflows/ci.yml`, deploy job only: (1) `IMAGE_REPO` becomes `${{ vars.BP_ECR_REGISTRY }}/beerpassport-admin-api`; (2) the two release-scan image references use the same ECR path; (3) the Docker Hub login step and its secrets are replaced by `aws-actions/configure-aws-credentials` (moved before publish) plus `aws-actions/amazon-ecr-login@v2`; (4) the SSM deploy step pins `--document-version 2`; (5) the server job gains an `ECR login helper checks` step running `scripts/test-ecr-login.py`. Because the agent's GitHub App cannot push workflow files (403 on tree creation, re-verified 2026-11-23), the updated workflow ships as a full replacement copy at `docs/ci-cd/workflows/ci.yml`; Codex or Frank installs it into `.github/workflows/ci.yml` on this branch. Every other file in the PR is pushed normally by the agent.

**What this PR does**

- The deploy job publishes the release image to the existing private ECR repository `beerpassport-admin-api` (us-east-1, account 149290600858) instead of the public Docker Hub repository, using the existing GitHub OIDC deployment role, which already has push permission to that repository (documented in `docs/ci-cd/github-ecr-push-policy.example.json`). The registry host comes from the GitHub variable `BP_ECR_REGISTRY`.
- The vulnerability policy is unchanged: Trivy scans the release image before publish, critical findings fail the job, high findings are reported as warnings. ECR scan-on-push on the existing repository is additive visibility, not the gate.
- Deployment still happens by immutable digest through the fixed SSM document, pinned to the new document version 2 (`docs/ci-cd/ssm-deploy-document.v2.json`), whose only change from version 1 is the ECR repository reference. Version 1 (Docker Hub) already exists and is retained unchanged; it remains the rollback path to the currently running image.
- Lightsail pull path (the host has no AWS CLI and ECR tokens expire after 12 hours): `scripts/deploy-api.sh` detects ECR references and, before pulling and before touching the running container, runs the new `scripts/ecr-login.py` (Python 3 standard library only; it makes the signed ECR GetAuthorizationToken call itself). The password is piped to `docker login --password-stdin`, never printed, and the login uses a temporary DOCKER_CONFIG directory that is deleted on exit. The primary credential source is the host's existing `/root/.aws/credentials` (default profile, including the session-token field; temporary credentials the SSM Agent maintains for the managed-node role, which carries the pull-only policy in `docs/ci-cd/lightsail-ecr-pull-policy.example.json`). A dedicated pull-only IAM user plus a root-only key file on the host is the documented fallback. Docker Hub references skip ECR authentication entirely, so rollback to the pre-migration image is preserved exactly.
- Runbook updated: what already exists, the pull-auth design, document version 2 creation, the pre-enable verification gate, and the cutover sequence with post-cutover Docker Hub token revocation.

**Test report**

- `bash scripts/test-deploy-api.sh` (also run by CI): the 4 pre-existing failure-restore scenarios pass (run, network, health, database), plus 3 ECR scenarios: login precedes the pull and the temporary docker config is removed; an ECR authentication failure aborts before the running container is touched; rollback after an ECR deploy returns to the recorded Docker Hub image without invoking ECR authentication.
- `python3 scripts/test-ecr-login.py` (also wired into CI): against a local stub ECR endpoint, the helper produces a correctly shaped SigV4 Authorization header and X-Amz-Target, pipes only the password to docker login's stdin, leaks neither password nor token to stdout, and fails before invoking docker when ECR denies the request.
- Both IAM policy examples parse as JSON and contain only IAM-supported statement keys (Version, Sid, Effect, Action, Resource); no `Comment` keys remain. `bash -n` clean on all shell scripts; `ci.yml` parses as YAML; the SSM document parses as JSON.
- Not verifiable from here, and explicitly gated in the runbook: a real ECR login and a real pull on the Lightsail host, plus any live ECR push or SSM execution. A real login and pull must be verified on the host before `BP_AUTO_DEPLOY_ENABLED` is set. No AWS or production change was made by this PR.

**Setup (nothing here is done by this PR; Frank/Codex run it)**

Already in place, do not recreate: the ECR repository `beerpassport-admin-api`; the deployment role's push permission to it; the SSM managed node; SSM document version 1.

1. Install the updated `.github/workflows/ci.yml` from `docs/ci-cd/workflows/ci.yml` (Codex/Frank; see the delivery note above) and merge the PR.
2. Set or verify the GitHub variable `BP_ECR_REGISTRY` = `149290600858.dkr.ecr.us-east-1.amazonaws.com`.
3. `aws ssm update-document --name BeerPassportDeployAdmin --content file://docs/ci-cd/ssm-deploy-document.v2.json --document-version '$LATEST'` (adds version 2; version 1 stays).
4. Confirm the managed-node role carries the pull policy (`docs/ci-cd/lightsail-ecr-pull-policy.example.json`); install `scripts/ecr-login.py` at `/opt/beerpassport-admin/` (root-owned, executable).
5. On the host, verify a real ECR login (`/opt/beerpassport-admin/ecr-login.py 149290600858.dkr.ecr.us-east-1.amazonaws.com`) and a real pull of a published digest. Both must succeed before enabling deployment.
6. Enable `BP_AUTO_DEPLOY_ENABLED` and dispatch; after the first ECR release verifies, revoke the Docker Hub token and delete its GitHub secrets.
